    Screenshot in Claude Code einfügen

    Bild unter Windows kopieren (z. B. Win+Shift+S), dann im Terminal Rechtsklick → Einfügen. Strg+V klappt fürs Bild nicht in jedem Browser — der Rechtsklick immer.

    Das Bild wird auf den Server hochgeladen und sein Dateipfad erscheint in der Eingabezeile — genau so liest Claude Code Bilder ein. Danach den Prompt einfach drumherum schreiben und mit Enter abschicken. Reiner Text lässt sich weiterhin ganz normal einfügen.

    Suche im Terminal-Verlauf

    Strg+F öffnet die Suche oben rechts (durchsucht die letzten 20.000 Zeilen). Enter springt zum nächsten, Shift+Enter zum vorherigen Treffer, Esc schließt. Treffer werden gelb markiert, der aktive grün.

    Agent-Status & Benachrichtigungen

    Läuft Claude Code oder Kimi in einer Session, zeigt der Punkt im Session-Eintrag den Status: grün = arbeitet, amber (pulsierend) = wartet auf eine Freigabe oder Antwort. Wird der Agent fertig oder stellt eine Rückfrage, erscheint im Browser-Tab ein ● vor dem Titel (verschwindet beim Zurückwechseln). Für echte Desktop-Benachrichtigungen den Schalter Benachrichtigung unten links aktivieren — der Browser fragt einmalig um Erlaubnis. Ein Klick auf die Meldung springt direkt zur betreffenden Session.

    Modell & Effort einer Agent-Session

    Läuft in einer Session claude, codex, grok oder kimi, steht unter dem Namen eine kleine Zeile mit dem aktuell benutzten Modell und dem Effort — etwa Opus 5 · medium. Beim Überfahren zeigt der Tooltip die vollständige Modell-ID und ob der Effort für diese Session gilt oder eine globale Einstellung des Tools ist (so bei kimi).

    Die Angaben kommen aus dem Sitzungszustand des jeweiligen Tools, nicht vom Bildschirm — ein Wechsel per /model oder /effort ist deshalb beim nächsten Antwortschritt zu sehen. Steht dort nichts, ließ sich die Session nicht zweifelsfrei zuordnen (etwa wenn zwei gleiche Tools im selben Verzeichnis laufen) — dann bleibt die Zeile lieber leer, statt womöglich das Falsche zu behaupten.

    Text markieren & kopieren

    Anwendungen wie Claude Code, vim oder htop fangen die Maus ab — normales Markieren geht dann nicht. Der Schalter Markieren & Kopieren im aktiven Session-Eintrag friert die Ansicht als markierbaren Text ein: Auswahl wird beim Loslassen kopiert, Esc kehrt zurück.

    Sessions

    Der Eintrag Standard ist eine persistente tmux-Sitzung — sie überlebt Seiten-Reload und Verbindungsabbruch. Startet man dort claude, codex, grok oder kimi, bekommt das Tool automatisch eine eigene tmux-Session und die Ansicht wechselt dorthin — die Standard-Shell bleibt frei. Darunter erscheinen alle weiteren tmux-Sessions; Claude-/Kimi-Sessions zeigen den aktuellen Aufgabentitel. Anlegen: +-Knopf neben der Überschrift, Name eingeben, Enter. Umbenennen: Stift-Symbol (bei Hover) oder Doppelklick auf den Namen, Enter speichert, Esc bricht ab. Beenden: ×-Knopf (bei Hover) — nach Rückfrage; beendet auch alle Prozesse in der Session.

    Wenn Claude ins Usage-Limit läuft

    Seit Claude Code 2.1.234 wartet die CLI ein erreichtes Limit selbst aus: es erscheint „Continuing automatically when your limit resets · esc to cancel", und nach dem Reset läuft die Aufgabe von allein weiter. Der Schalter dazu heißt in /config „Continue automatically at usage limit" und ist ab Werk an. Wichtig: das Warten passiert im laufenden Prozess — die Session muss offen bleiben. Wird claude beendet oder neu gestartet (auch durch ein Update per Self-Update), ist die Wartung weg; dann nach dem Reset einfach einen Prompt abschicken.

    Das Zusatzpaket claude-auto-retry (ein tmux-Monitor außerhalb der Session) war genau dafür gedacht und ist deshalb nicht mehr nötig — der Installer schlägt es nur noch mit „nein" vor. Es kann weiterhin drei Dinge, die das eingebaute Feature nicht tut: erneut versuchen bei anhaltender API-Überlast (API Error: 529), erneut versuchen bei Safeguard-Fehlalarmen („safeguards flagged this message") und die Aufgabe nach einem Neustart des Prozesses wieder anstoßen.

    Laufen beide auf denselben Fall, kann es doppelt zünden: der Monitor liest nur den Bildschirminhalt und weiß nichts vom eingebauten Warten — im Zweifel landet nach dem Reset ein zweites „continue" in der Session. Wer das Paket behält, schaltet darum am besten eine der beiden Seiten ab: entweder den Usage-Limit-Teil in ~/.claude-auto-retry/config.json oder das eingebaute Fortsetzen in /config.

    Dateien & Editor

    Rechte Spalte: Klick öffnet bzw. lädt herunter, Bilder zeigen beim Überfahren eine Vorschau, Rechtsklick öffnet das Menü (u. a. Bearbeiten). Hochladen per Drag & Drop vom Desktop. Im Editor speichert Strg+S, Strg+F sucht in der Datei.

    Self-Update

    Das runde Pfeil-Symbol oben zeigt den Update-Stand der Installation: dezent = aktuell, gelb pulsierend mit Zähler = neue Version verfügbar. Beim Überfahren erklärt ein Hinweis, was ein Klick tut: Ist alles aktuell, wird nur neu geprüft; gibt es ein Update, startet nach Rückfrage deploy/update (git pull, Build, bei Backend-Änderung ein sessions-schonender Neustart — laufende Claude-/Kimi-Sessions kommen automatisch zurück). Danach lädt die Seite bei Bedarf selbst neu.

    Bugtracker

    Das Käfer-Symbol oben links (neben dem Update-Icon) öffnet den Bugtracker. Er hängt an den GitHub-Issues des Projekt-Repos — alle Installationen melden in dieselbe Liste, jeder sieht die Bugs der anderen. Anlegen: Titel eintragen, optional Details, Enter im Titelfeld legt an (in den Details Strg+Enter) — es entsteht ein Issue, dein GitHub-Konto ist der Autor. Das Häkchen schließt bzw. öffnet den Issue wieder (= erledigt); offene zählt der Zähler am Symbol. #Nummer öffnet den Issue auf GitHub.

    Voraussetzung je Installation: einmalig gh auth login mit Zugriff aufs Repo. Fehlt der Zugang, zeigt das Panel statt der Liste einen Einrichtungs- Hinweis — es gibt bewusst keinen lokalen Ersatzspeicher.

    Spaltenbreite anpassen

    Die Trennlinien von Sidebar (links) und Datei-Explorer (rechts) lassen sich mit der Maus ziehen — der Zeiger wird dort zum ↔. Doppelklick auf die Linie setzt die jeweilige Spalte auf die Standardbreite zurück. Die gewählten Breiten bleiben im Browser gespeichert. Praktisch, wenn der Servername oben links für die schmale Sidebar zu lang wird.

    Smartphone & Diktat

    Auf schmalen Bildschirmen (iPhone & Co.) klappt die Ansicht um: ☰ öffnet die Sessions, das Ordner-Symbol die Dateien, beides als Schublade über dem Terminal. Unten sitzt eine Eingabeleiste: Text dort eintippen oder per Mikro der Tastatur diktieren und mit → (bzw. Enter) abschicken — das kommt sauber im Terminal an, auch bei Claude Code. Darunter Sondertasten, die die Handy-Tastatur nicht hat: Esc, Tab, Ctrl (gilt für die nächste getippte Taste), ^C, Pfeile, Enter. Das Tastatur-Symbol in der Kopfzeile blendet die Leiste aus, falls man lieber direkt ins Terminal tippt.

    Links & Darstellung

    Im Terminal erkannte URLs sind direkt klickbar und erscheinen zusätzlich gesammelt unten links — auch wenn sie über mehrere Zeilen umgebrochen sind (praktisch beim /login von Claude). Hell-/Dunkelmodus: Schalter unten links, die Wahl bleibt im Browser gespeichert.
